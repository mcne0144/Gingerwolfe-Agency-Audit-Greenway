## 1. Purpose

This template produces the **Paid media** rows for `expansion-signals.md` (Capability values: Paid media / Reviews & reputation / Content production / Systems & automation / Additional rooftops). It exists so the operator can hand one row to a single GM — in a one-on-one, at the Month 6 readout, or whenever she decides — without it reading as a pitch.

**What makes a row ready to hand over (plain-language test):**
- A GM reads it on a phone between customers and understands it in one pass.
- It names the store's real, observed gap — not a generic "you should run ads."
- It proposes a test, not a program; a number, not a promise; a next step the GM can say yes or no to.
- No hype adjectives, no urgency, no pricing of Bright Matter services, no invented facts.

**What makes a row NOT ready:** speculation presented as fact, invented store data, an unverified offer, a pitch for services, or a budget bigger than a test. When in doubt, the row stays in the working file with **TO VERIFY** markers — it never reaches the log half-verified.

## 2. The template (fill one row per opportunity)

| Field | What goes here |
|---|---|
| **Rooftop** | Store code + name + market (e.g., "Store 01 — Greenway Kia West Palm Beach, FL") |
| **Observed gap** | The store's real gap, in one sentence, in plain language. Drawn ONLY from store data: `audit/workbook/` findings, `stores/store-XX/STORE.md`, `channel-matrix.csv`, GM one-on-one notes (via Shannon). No invented gaps. |
| **Supporting evidence** | What was observed, when, and from where (e.g., "GBP rating 4.5★ observed 2026-08-12, audit workbook store-01; listing posts quiet after Jun 18, 2026"). Label source type (observed public data / operator context / TO VERIFY). |
| **Capability implied** | **Paid media** (this template). If the real fix is reviews or content, the row belongs to that capability — paid is only implied when paid is a genuine lever for THIS gap. |
| **Proposed test (structure + budget as PROPOSAL)** | One test, 2–3 lines: layer from `PAID_MEDIA_FRAMEWORK.md` §2, platform, geo, creative source, duration, budget — all labeled **PROPOSAL — for Shannon's approval**. |
| **Close at no charge?** | Yes/No + why. If the gap closes with pilot-scope work (e.g., restarting organic posting) the paid test is unnecessary or premature — say so. Only label "pilot goodwill" per `OPERATING_RULES.md` §2.3 rules. |
| **Operator seen?** | No (this template's default). The operator marks Yes when she has reviewed the row. |
| **Status** | Open / In discussion with GM (only the operator moves it) / Deferred / Closed — mirror `expansion-signals.md`. |

## 4. How rows flow into `expansion-signals.md`

1. Paid Media Specialist drafts rows here (this file) with evidence + TO VERIFY markers, and logs the **Paid media** capability rows into `expansion-signals.md` (same columns, same statuses) — the Team Lead owns the log and reviews it with the operator before every GM one-on-one and at Month 6.
2. The operator marks **Operator seen?** = Yes when reviewed, and decides what gets raised, when, and with which GM.
3. If the GM says yes to a test, the budget is still a **PROPOSAL for Shannon's approval**; execution requires the scope-expansion + access gate (`CAMPAIGN_SETUP_GUIDE.md` §1).
4. If the real fix is pilot-scope (organic restart, listing cleanup), that part is labeled "included at no charge — pilot goodwill" per `OPERATING_RULES.md` §2.3 and counted in the goodwill tally — never silent.
5. Rows age: any row relying on data from 2026-08-12 must be re-verified at the next audit round before it goes to a GM.

**Evidence rules (non-negotiable):**
- Every gap cites a real observation with a date and source (audit workbook, stores/, channel-matrix.csv, operator context, GM notes via Shannon).
- No invented store facts, offers, or numbers. **TO VERIFY — request from client via Shannon McNeil** markers stay until data arrives.
- No pricing of Bright Matter services anywhere in a row. Budgets are labeled **PROPOSAL** and belong to the client's media-spend decision, not to the retainer.
